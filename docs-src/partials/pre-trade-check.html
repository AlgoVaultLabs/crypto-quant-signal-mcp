Checks a crypto perpetual futures order against your own rules. Each rule passes or fails with its numbers, then the check returns GO, CAUTION or WAIT. It adds the isolated liquidation distance and whether it hits before your stop, fees, the accuracy needed to break even over your hold, funding by venue (cross-venue) and the market regime. Read-only: it places no orders.

Parameters

Name Type Description
coinstringAsset symbol, e.g. BTC, ETH, SOL. Required
sizeUsdnumberOrder notional in USD, e.g. 10000. Above 0, up to 100,000,000. Required
holdHoursnumberExpected holding time in hours (0.25–720); sets the funding cost window. Default: 8
leveragenumberIsolated leverage you will use, e.g. 10. Enables the liquidation checks (1–200). Optional.
stopPctnumberStop-loss distance from entry in percent, e.g. 2 (0.01–50). Optional.
targetPctnumberTarget distance from entry in percent, e.g. 4 (0.01–1000). Optional.
equityUsdnumberAccount equity in USD. Enables the percent-of-equity rules. Above 0, up to 10,000,000,000. Optional.
rulesobjectYour rules, each key optional. Saved rules apply too; a failed one returns WAIT. Every key is listed below. Optional.

Your rules

Every key the rules object accepts. An unknown key is refused, unbilled.

Key Range Default What it checks
maxLeverage1–200—Highest leverage you allow.
noLiqBeforeStopbooleanonFail if liquidation would come before your stop. Default on.
minLiqDistanceSigma0–50—Liquidation at least this many hold-period volatilities away.
maxLossAtStopPctEquity0–100—Most equity, in percent, you accept losing at your stop.
maxDailyMovePctEquity0–100—Largest equity swing, in percent, from a one-sigma daily move.
maxRoundTripBps0–1000—Highest round trip in fees plus spread, in bps.
maxAccuracyNeededPct50–100—Highest direction accuracy, in percent, needed to break even.
maxFundingBps0–1000010Highest funding over the hold, in bps. Default 10.
maxSizePctOf24hVolume> 0, ≤ 1000.1Largest order as a percent of a venue's 24h volume. Default 0.1.
regimeCheckbooleanonFlag a regime against your side or a volatile one. Default on.
  • Every key you send is active, with source yours. The four rules with a default are active unless you switch them off, with source default.
  • false switches a boolean default off. A number replaces a default and makes the rule yours.
  • A max key fails strictly above its limit and a min key strictly below. maxFundingBps fails at or above its limit, maxSizePctOf24hVolume when the order is above a venue’s capacity at that limit, and noLiqBeforeStop when liquidation is at or inside your stop.
  • A rule whose figure needs an input you did not send is not_evaluated, and its detail names what to send. Liquidation is computed on each venue that publishes its margin tiers.
  • A rule of yours that fails returns WAIT (YOUR_RULE_FAILED). A rule of yours that could not be checked, or a default that fails, returns CAUTION.

Saved rules

Save your rules once. Send them to PUT https://api.algovault.com/api/pre-trade-rules with your API key (Authorization: Bearer <key>). Every check made with that key then applies them, marked saved in rules[]; a rule sent with a call overrides the saved one for that call. GET shows what is saved and DELETE clears it. Saving needs an API key; a free key works.

Recipe

A 5× long, a 2% stop, and your own leverage cap

pre_trade_check({ coin: "BTC", side: "long", sizeUsd: 10000, leverage: 5, stopPct: 2, rules: { maxLeverage: 10 } })

maxLeverage passes at 5×. The leverage and stop also let the default noLiqBeforeStop rule be checked, on each venue that publishes its margin tiers. Send leverage: 20 instead and your rule fails: the decision is WAIT, with YOUR_RULE_FAILED in reasons.

Call it over HTTP

curl -s -X POST https://api.algovault.com/mcp \
  -H "Authorization: Bearer $ALGOVAULT_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pre_trade_check","arguments":{"coin":"BTC","side":"long","sizeUsd":10000,"leverage":5,"stopPct":2,"rules":{"maxLeverage":10}}}}'

The response is an event stream: the tool result is JSON on the data: line, in result.content[0].text.

Refusals

A refusal comes back as a tool error with result.isError: true. Every refusal is unbilled.

Code When, what it carries, and what to do
hosted_onlyYou called it on a local install of the server. The check reads the hosted bar-close snapshot, so a local install refuses it before it runs. Carries hosted_endpoint. Add https://api.algovault.com/mcp as a remote MCP server in your client and call it there.
-32602An argument the schema does not declare, at the top level or inside rules, or a value outside its range. The text in result.content[0].text names the key and its path. See Errors & troubleshooting.
TIER_LIMIT_REACHEDYour call allowance is used up. Carries resets_at, suggested_action and suggested_x402, the pay-per-call route for this tool. See Errors & troubleshooting.

A check charges one call on your plan, whatever the decision, or $0.02 over x402. Refusals are free. It is informational and read-only: it places no orders.

Gate your orders

Make the check a step your agent cannot skip. In Claude Code, the AlgoVault pre-trade gate plugin blocks an order tool call until pre_trade_check has recently checked that coin and side, and blocks it when the check returns WAIT. In LangChain, a middleware runs the check before your order tool; in Freqtrade, confirm_trade_entry skips the entry on WAIT. Each recipe blocks the order when the check cannot run, and lets CAUTION through with its reasons. The same gate also runs in Codex.
